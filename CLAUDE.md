# Verbal CRM — контекст проекта

CRM/LMS репетитора по **SAT Reading & Writing** (владелец — Нурасыл, GitHub `NuraAtWork`).
Сейчас инструмент для собственной работы с учениками; в планах — **продавать доступ к этой LMS**
(кому именно — ученикам, репетиторам или школам — пока не решено; уточнять у пользователя).

- Сайт: https://nuraatwork.github.io/sat-verbal-crm/ (GitHub Pages, деплой на каждый push в `main`)
- Репозиторий: https://github.com/NuraAtWork/sat-verbal-crm (публичный — см. «Чего нельзя»)
- Доска задач: https://github.com/users/NuraAtWork/projects/2 (issues с метками `отложено`, `идея`)
- Интерфейс и общение с пользователем — **на русском**.

## Что умеет

- **Ученики**: статус, контакты, старт/цель/последний балл R&W, дата экзамена, график баллов, пробные тесты,
  журнал уроков (темы-навыки, ДЗ, оплата), покрытие 11 навыков цифрового SAT по 4 доменам.
- **Материалы**: папки «Вопросы по категориям» (компактные строки: навык → номера сетов с полоской сложности,
  клик раскрывает детали: Открыть / Задать) и «Прошлые тесты» (карточки).
- **Сеты вопросов и задания** (только облачный режим): репетитор задаёт сет ученику → ссылка
  `#/solve/<token>` → ученик без входа решает по одному вопросу с таймером на каждый вопрос → ответы
  проверяются **на сервере** → ученик видит балл и разбор, репетитор в карточке ученика — ответы, ошибки,
  пропуски и время по вопросам.
- **Библиотека материалов — только чтение** для репетитора (`src/permissions.ts`, `CAN_EDIT_LIBRARY = false`):
  кнопки создания/правки/копирования/удаления скрыты, `/sets/new` и `/sets/:id/edit` перенаправляют на просмотр.
  Редактор сетов (`SetEditor`) остаётся в коде для будущей роли «админ платформы».
- **Данные**: экспорт JSON, «Восстановить из копии» (замена), «Добавить из файла» (merge, в т.ч. сеты).
- Светлая тема по умолчанию, тёмная — переключатель в боковой панели.

## Стек и устройство

Vite + React 19 + TypeScript (~7), `react-router-dom` (**HashRouter**), `@supabase/supabase-js`, oxlint,
шрифт `@fontsource-variable/inter`, иконки `lucide-react`, `dompurify` для HTML вопросов.

| Файл | Что там |
|---|---|
| `src/types.ts` | Student, Lesson, ScoreEntry, Material (+setId), QuestionSet, Assignment |
| `src/db.ts` | редьюсер и `Action` (`*/upsert`, `*/delete`, `db/replace`, `db/merge`), `normalizeDb` (миграции старых данных) |
| `src/store.tsx` | `LocalStore` (localStorage) / `CloudAuth` + `CloudStore` (оптимистичные изменения, очередь запросов в Supabase, перечитывание при ошибке) |
| `src/remote.ts` | маппинг строк Supabase ↔ типы, `fetchAll`, `applyRemote` |
| `src/sets.ts` | API сетов и заданий (загрузка сетов, задания, RPC ученика), `formatDuration` |
| `src/solve/SolveApp.tsx` | страница ученика (отдельный корень в `main.tsx`, без CRM и входа) |
| `src/pages/*`, `src/components/*` | экраны и компоненты CRM |
| `src/index.css` | дизайн-токены (светлая/тёмная тема через `:root[data-theme='dark']`) и стили CRM |
| `src/sets.css` | вопросы («бумага» всегда светлая), задания, страница ученика |
| `supabase/schema.sql` | вся схема БД, идемпотентная (можно запускать повторно) |
| `tools/` | скрипты подготовки сетов вопросов из Google Drive (см. ниже) |

**Два режима данных** (выбираются при сборке):
- облачный — если заданы `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` (в CI — переменные репозитория
  `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`);
- локальный — иначе (всё в localStorage; демо-данные доступны только тут).

**Supabase**: проект `sat-verbal-crm` (ref `sxiykdtpnjxmstwfjgsq`), организация «SAT Tutoring», Free план, Европа.
Регистрация выключена; один пользователь-репетитор. Таблицы: `students`, `lessons`, `scores`, `materials`
(`set_id`), `question_sets` (`questions` jsonb без ключа + `answers text[]`), `assignments` (`token`).
У всех таблиц RLS «только свои строки» (`owner_id = auth.uid()`), у `anon` нет доступа к таблицам.
Ученик работает только через `security definer` функции `get_assignment` / `start_assignment` /
`submit_assignment` — ключ не уходит до сдачи, пересдать нельзя. Изоляция аккаунтов уже готова
для мульти-тенантной продажи.

## Сеты вопросов

Исходники — HTML-файлы на Google Drive пользователя (Drive for Desktop, `G:\My Drive\...`):
`nurassyl.bolat@alumni.nu.edu.kz/My Drive/GRE/Students/Stepan/SAT Questions/<Category>/<Category>_Set_NN.html`
(папки `_old` не используются). Сейчас загружено 60 сетов / 1431 вопрос.

Импорт: `tools/drive_ids.py` (ID файлов из локальной базы Drive for Desktop) →
`tools/parse_sets.py` (разбор HTML → вопросы, варианты, ключ; санитизация; JSON для «Данные → Добавить из файла»).
Повторный импорт идемпотентен (id = uuid5 от ссылки на Drive).

## Чего нельзя

- **Не коммитить содержимое вопросов, ключи ответов и данные учеников** — репозиторий публичный.
- Не трогать secret/service_role ключ Supabase и пароли — только publishable key (он публичный по дизайну).
- Не использовать демо-данные / `db/replace` в облачном режиме без явного подтверждения (стирает данные).

## Как работать

```bash
npm install
npm run dev        # локально; для облака — .env.local по образцу .env.example
npm run lint && npm run build
```

Коммиты — на английском, с `Co-Authored-By`; деплой — push в `main` (GitHub Actions → Pages).
SQL-изменения: дописывать в `supabase/schema.sql` идемпотентно и применять через SQL Editor Supabase.

## Решения и планы

- Дизайн: «современный SaaS» (акцент индиго `#5b5bd6`, Inter, lucide-иконки), бренд **Verbal CRM**.
- Ученик после сдачи видит балл и разбор ошибок; результаты хранятся на сервере, скриншоты не нужны.
- Отложено/идеи: группы учеников; бэкап результатов в экспорт; сохранение прогресса ученика на сервере
  по ходу решения; привязка материалов к урокам (#2); расписание (#3); продажа доступа
  (регистрация, оплата, тарифы); Supabase Pro ($25/мес) — когда понадобятся бэкапы и отсутствие «засыпания».

## Пробные тесты

Тест = сет с `kind: 'test'`, `modules: [{title, count, minutes}]`, `explanations[]`; у вопроса — `module` и `skill`
(навык определяется по формулировке, пусто — если неясно). Импорт: `python tools/parse_tests.py <out.json> <pdf>...`
(PDF FlashSAT; Math пропускается) → «Данные → Добавить из файла»; в «Материалах» — папка «Прошлые тесты».
Ученик (`src/solve/TestSolve.tsx`): модули по очереди, таймер модуля по часам сервера (`module_starts`), сдача модуля —
RPC `start_test_module` / `submit_test_module`, вернуться в сданный модуль нельзя; после сдачи — оценка балла 200–800
(грубая таблица `estimate_rw_score`, не официальная шкала) и разбор с объяснениями. Опоздание сверх лимита (+2 мин)
не отбрасывает ответы, а помечает модуль `late` — репетитор видит это в списке заданий.

## Тренер словаря (Words in Context)

Ученик открывает постоянную ссылку `#/vocab/<token>` (без входа; `#/vocab/demo` — демо со словами-примерами,
прогресс в браузере) и каждый день проходит сессию: карточка нового слова → упражнения. Код: `src/vocab.ts`
(типы, выбор упражнения, API), `src/vocab/VocabApp.tsx` (страница ученика), `src/vocab/demo.ts`,
`src/components/StudentVocab.tsx` (блок «Словарь» в карточке ученика: включить тренер, ссылка, лимит новых слов,
активность за 14 дней, трудные слова).

- Таблицы: `vocab_words` (слово, определение, перевод, `contexts` jsonb — предложения с `____`, дистракторы,
  пояснение), `vocab_enrollments` (ученик + `token` + `new_per_day`), `vocab_progress` (ступень 1–7, `due_at`),
  `vocab_reviews` (журнал ответов). RPC ученика: `vocab_session` / `vocab_review`; репетитора: `vocab_stats`.
- Ступени: 1 — «слово → значение» в той же сессии; дальше пропуск в контексте (нет контекстов — «значение →
  слово»). Верно — ступень +1, показ через 1/3/7/16/35/70 дней; ошибка — откат и повтор в этой же сессии.
  Правило продублировано в `nextStage` (клиент) и `vocab_review` (SQL) — менять в обоих местах.
- Это тренировка, а не контроль: слова уходят ученику вместе с ответами, проверка в браузере.
- Слова: `python tools/extract_vocab.py <файл импорта сетов> <out-import.json>` собирает кандидатов из сетов
  Words in Context (определения и перевод пустые — заполнить), затем «Данные → Добавить из файла» (`vocabWords`).
- Этап 2 (блок «Тренер словаря, этап 2» в schema.sql): личная очередь `vocab_student_words` — эти слова тренер
  вводит первыми. В неё попадают верный и выбранный варианты из вопросов Words in Context, где ученик ошибся (триггер →
  `vocab_queue_from_assignment`, слова узнаются по `vocab_words.forms`), и слова по клику в разборе задания
  (`src/vocab/WordLookup.tsx` → RPC `vocab_lookup` по токену задания; слова вне словаря копятся в `vocab_requests`).
- С 3-й ступени упражнение с пропуском сначала прячет варианты («сначала подумай сам», `PREDICT_STAGE`), после
  ответа под неверными вариантами показывается их значение (`glossary` из `vocab_session`).
- Отдельной ступени «настоящий WIC-вопрос» нет: контексты слов и так взяты из вопросов банка целиком.
- Этап 3: с 5-й ступени (`TYPE_STAGE`) вариантов нет — слово вписывают (`checkTyped`: форма из контекста или
  начальная, одна опечатка засчитывается с пометкой «почти»). Страница «Словарь» (`#/words`,
  `src/pages/VocabWords.tsx`, `src/vocabAdmin.ts`): поиск, добавление и правка слов и контекстов, просьбы учеников
  (после добавления слова просьба закрывается, слово встаёт в очередь ученика). На «Обзоре» — карточка «Тренер
  слов» (`VocabOverview`, RPC `vocab_overview`): кто когда занимался. Словарь — личные данные репетитора, поэтому
  `CAN_EDIT_LIBRARY` на него не действует.
- Перед экзаменом: за 2 дня до `students.exam_date` и в день экзамена `vocab_session` не выдаёт новых слов, только
  повторение (`EXAM_QUIET_DAYS` в `src/vocab.ts` и то же число в SQL); прошедшая дата экзамена ничего не блокирует.
- Отложено: FSRS (нужна история ответов, сейчас её почти нет), напоминания ученику (нет канала связи: ни входа,
  ни бота), колоды в интерфейсе (`deck` уже в схеме).

## Тренер грамматики (Boundaries; дальше — другие навыки Conventions)

Ученик открывает постоянную ссылку `#/grammar/<token>` (без входа; `#/grammar/demo` — демо с тремя правилами,
прогресс в браузере). Единица тренировки — **правило** (а не вопрос): карточка (суть, объяснение, примеры
верно/неверно, быстрая проверка) + 10 своих упражнений в формате SAT (пропуск и 4 варианта, у каждого варианта —
почему верно/неверно и метка ловушки). Код: `src/grammar.ts` (типы, выбор упражнения, `STRUCTURES`, `TRAPS`, API),
`src/grammar/GrammarApp.tsx` (страница ученика), `src/grammar/demo.ts`, `src/components/StudentGrammar.tsx`
(блок «Грамматика» в карточке ученика: включить, ссылка, правил в день, ступени по правилам, ловушки за 30 дней,
точность шага «структура», активность за 14 дней). В кабинете ученика — раздел «Грамматика» и строка на Главной.

- Таблицы (блок «Тренер грамматики» в schema.sql): `grammar_rules` (`skill`, теория, `examples`, `items` jsonb),
  `grammar_enrollments` (ученик + `token` + `new_per_day`, по умолчанию 2; `skills` — пусто = все),
  `grammar_progress` (ступень 1–7 по правилу), `grammar_reviews` (журнал: `item_id`, `trap`, `structure_ok`).
  RPC ученика: `grammar_session` / `grammar_review`; репетитора: `grammar_stats`; `student_home` отдаёт `grammar`.
- Сессия: новые правила (карточка → разминка `warmup`, ступень не меняет → упражнение, которое переводит на 2-ю) и
  повторения (по упражнению на правило, вперемешку). Ступени и интервалы — как у словаря; правило продублировано в
  `nextStage` (`src/grammar.ts`) и `grammar_review` (SQL). Ошибка — правило возвращается в эту же сессию с другим
  предложением. Упражнение выбирается так: ещё не виденное → по трудности под ступень (1–2 → лёгкие, 5+ → трудные) →
  давно виденное (`recent` из `grammar_session`).
- До 3-й ступени (`STRUCTURE_STAGE`) правило подписано (`cued`); дальше — «как на экзамене» (`sat`): сначала шаг
  «что слева и справа от пропуска?» (если у упражнения задан `structure`), потом выбор знака. Перед экзаменом новые
  правила не вводятся (как в словаре).
- Анализ банка (189 вопросов Boundaries, slug `boundaries`; Hard — больше половины) дал 13 правил: два полных
  предложения; вводная часть; оборот после главного; не разделять связанное; звание + имя; вставка в парных знаках;
  обязательное уточнение или вставка; двоеточие/тире; however между предложениями; связка на стыке (к какому
  предложению относится); одно подлежащее — два действия; перечисления с «;»; прямой/косвенный вопрос.
- **Контент — свой и не в git**: предложения написаны с нуля по правилам, без пересказа вопросов банка; перед
  загрузкой проверено, что нет совпадающих цепочек из 5 слов с текстами банка. Правила загружаются через
  «Данные → Добавить из файла» (ключ `grammarRules`, файл `*-import.json` в .gitignore). В репозитории — только демо.
- Новый навык (Form, Structure, and Sense; Transitions) = новые правила с другим `skill` и, при желании, свой список
  в `STRUCTURES` и метки в `TRAPS`; схема не меняется. Для Transitions шаг «структура» можно заменить на
  «какая связь между предложениями».
- Отложено: страница «Правила» в CRM (просмотр и правка, как «Словарь»), правила из ошибок в заданиях
  Boundaries (как очередь слов), смешанный «экзаменационный» режим без привязки к правилу.

## Кабинет ученика

Постоянная ссылка `#/me/<token>[/<раздел>]` без входа (`#/me/demo` — демо с выдуманным учеником). Только чтение.
Слева панель разделов (на телефоне — лента сверху): Главная (что сделать сейчас), Домашние задания (сеты),
Разбор тестов (пробные тесты), Аналитика (точность по навыкам), Уроки (темы, история, ДЗ), Путь к экзамену
(старт → сейчас → цель, график баллов), Словарь (вход в тренер), Грамматика (вход в тренер грамматики). Задания открываются в `#/solve/<token>`,
слова — в `#/vocab/<token>`. Код: `src/portal.ts` (типы, API), `src/portal/PortalApp.tsx` (каркас и разделы),
`src/portal/demo.ts`, `src/components/StudentPortal.tsx` (блок в карточке ученика: открыть, ссылка, закрыть).

- Таблица `student_portals` (ученик + `token`); всё содержимое отдаёт одна RPC `student_home(p_token, p_day_start)`.
  Оплата, заметки репетитора и контакты ученику не отдаются — новые поля добавлять в функцию осознанно.
- Блоки `Soon` («скоро») — затычки под будущие функции: работа над ошибками, разбор теста по типам ошибок,
  комментарий преподавателя, динамика и сложность в аналитике, следующий урок и материалы урока, план до экзамена,
  список «Мои слова». Делая функцию, заменять затычку настоящим блоком.
- Пороги «слабый/сильный навык» в кабинете повторяют `src/analytics.ts` (`MIN_SAMPLE`, 70% / 85%).
- Сменить ссылку = закрыть кабинет и открыть заново (строка удаляется, токен новый).
- Страницы задания и словаря показывают «← Мой кабинет» (`PortalBack`), если ученик пришёл из кабинета
  (токен кабинета лежит в `sessionStorage`).

## Уроки и конструктор

Раздел «Уроки» в CRM (`#/lessons`, `src/pages/Lessons.tsx`): вкладки «Уроки» (все уроки по ученикам) и «Заготовки».
Конструктор — `src/pages/LessonEditor.tsx` (один редактор для урока и для заготовки). Блоки урока идут в порядке
обратного дизайна: тема и навыки → цели → «хороший результат» (по чему видно, что цель достигнута) → теория →
практика на уроке (текст + сеты) → ДЗ (текст + сеты) → итог после урока (достигнут / частично / нет + заметки).

- Содержание лежит в `lessons.plan` (jsonb, тип `LessonPlan`); у старых уроков его нет — читать через `l.plan?.`.
  Темы-навыки, текст ДЗ, заметки и оплата остались прежними полями урока.
- Заготовки — только свои: таблица `lesson_templates` / `db.lessonTemplates` (действия `template/upsert`,
  `template/delete`; попадают в экспорт и merge). Готовых заготовок в коде нет: пользователь решил собирать их
  с нуля (у уроков, созданных до этого, в `plan.templateId` может остаться `preset:<...>` — это безвредно).
- Новый вид раздела сначала отрабатывается на HTML-мокапе (файл на рабочем столе пользователя,
  `verbal-crm-lessons-mockup.html`: урок из переставляемых блоков, тайминг, вид «глазами ученика»), потом
  переносится сюда.
- Сеты «на дом» при сохранении урока в облаке становятся заданиями ученика с `assignments.lesson_id`
